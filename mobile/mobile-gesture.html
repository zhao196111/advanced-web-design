三条验收，自己就能验： ① 手指只划一小段（< 40px）松手，卡片不动； ② 快速连划两次，只前进一张，不会跳两张； ③ 在卡片上上下拖，页面跟着滚，不会被卡片"吃掉"。

// 判定"这一次算不算滑动"
var wy_dx = wy_endX - wy_startX;
var wy_dy = wy_endY - wy_startY;

if (Math.abs(wy_dx) < 40) return;          // ① 阈值：不够远，当误触
if (Math.abs(wy_dx) < Math.abs(wy_dy)) return;   // ② 主方向不是横向，交给页面滚动

if (wy_now - wy_last < 300) return;          // ③ 冷却：挡住连滑
wy_last = wy_now;

wy_dx < 0 ? wy_next() : wy_prev();              // ④ 左滑下一张，右滑上一张

为什么容器要写 touch-action PAN-Y

不写这一句，手指一横向拖动，浏览器会先当成"页面要被拖动"，再把事件断断续续地报给 JS， 手感发飘、还会带着整页抖。写成 pan-y 等于告诉浏览器：纵向的平移你拿去滚动， 横向的别管，交给我。注意只加在卡片容器上，加到 body 上整页就滚不动了。

03

答辩准备

Q & A
Q1阈值设成 5px 会怎样？
几乎每次点击都会被判成滑动。手指按下去的瞬间会有 3～8px 的位移抖动，5px 的门槛挡不住， 于是"想点一下"变成"翻了一页"，而且点击和滑动互相打架。反过来设成 120px，用户得把手指划到屏幕边缘才有反应， 会觉得"这页面坏了"。40px 是经验值：大于抖动、小于一次自然的滑动。
Q2冷却 300ms 是怎么起作用的？
每次切换成功时记下时间戳 wy_last = Date.now()。下一次 touchend 进来先算差值， 小于 300ms 就直接 return，只弹一句"别太快"。这样即使手指连划两下，第二下也被吃掉， 不会出现"一次手势跳两张"。
Q3为什么 touchmove 里没有写 preventDefault？
因为容器已经用 touch-action: pan-y 声明了横向手势归自己，浏览器不会再拿横向去滚页面， 不需要再 preventDefault。真要写的话还得加 { passive: false }， 否则浏览器会警告"passive 监听器里不能阻止默认行为"——这也是移动端最常见的一个坑。
Q4加了 touchcancel 有什么用？
来电、下拉通知、系统手势会把触摸"抢走"，这时只有 touchcancel 没有 touchend。 如果只在 touchend 里复位状态，被 cancel 后 wy_startX 还是上一轮的旧值， 下一次滑动算出来的位移就是错的。本页把收尾工作写在一个函数里，两个事件都调它。
