02

"缩放不跳"是怎么做到的

WHY NO JUMP

很多人第一次写缩放都会跳：两指一动，图片"啪"地弹到左上角。原因是只改了 scale， 没有同时修正 translate。图片以自身中心为原点放大，原来在手指下的那一点就被推走了。

正确做法是：手势开始时，把两指中点、当前倍数、当前位移都存下来； 每一帧算出新倍数后，用"中点要保持不动"这个条件反推新的位移： 

// 手势开始时存下的快照
wy_startDist  = 两指距离
wy_startScale = 当前倍数
wy_startMid   = 两指中点（屏幕坐标）
wy_startTx    = 当前位移

// 每一帧：倍数按距离比例变化
wy_scale = clamp(wy_startScale * (wy_dist / wy_startDist), 1, 4);
wy_k = wy_scale / wy_startScale;

// 位移跟着修正：让"起点中点下的那张图"仍然落在"现在中点"下面
wy_tx = wy_mid.x - wy_cx - wy_k * (wy_startMid.x - wy_cx - wy_startTx);
wy_ty = wy_mid.y - wy_cy - wy_k * (wy_startMid.y - wy_cy - wy_startTy);

其中 wy_cx / wy_cy 是查看器中心。wy_k 是"这一帧相对手势开始放大了多少倍"， 用它去缩放"中点相对中心的那段偏移"，中点就钉住了。位移是算出来的，不是猜的。

验收点本页怎么处理
缩放以两指中心为基准用上面的公式反推 translate，中点不动
边界有阻尼或限制倍数夹在 1～4；越界拖动只允许再走 25%，松手回弹到边界
1× 时不能拖出边界倍数为 1 时位移强制归零，拖动直接忽略
缩放后旋转屏幕不丢状态倍数与位移都在 JS 状态里，resize 只重算边界、重新夹紧，不清零
双击 1× / 2× 切换两次点击间隔 < 300ms 判双击，带 0.25s 过渡

为什么 touch-action 必须写 none TOUCH-ACTION

双指张开的默认行为是"缩放整个页面"。不把 touch-action 设成 none， 浏览器会先把手势当成页面缩放，你的 touchmove 收到的坐标是断的， 而且整个页面被放大后布局全乱。写了 none 之后，手势完全交给 JS， 还要在 touchmove 里 preventDefault() 兜住老浏览器的默认行为。

04

答辩准备

Q & A
Q1双指缩放时怎么保证图片不"跳"？
缩放和位移必须一起算。只改 scale 的话，图片围绕自身中心放大，手指下的那一点会被推走， 看起来就是"跳"。这里在 touchstart 存下两指中点、当前倍数、当前位移， 每帧按 wy_k = 新倍数 / 旧倍数 修正位移，让起点中点下的图仍然落在现在中点下—— 中点钉住了，图就不会跳。
Q2为什么用"每帧比例"而不是直接算总倍数？
touchmove 里两指距离一直在变，直接拿"当前距离 / 起始距离"当倍数，遇到手指中途换姿势 （一根手指抬起又落下）会突然跳变。用"本帧距离 / 上帧距离"累乘，每一步都是小变化， 再加上 1～4 的夹紧，画面就是连续的。
Q3缩回 1× 为什么能自动居中？
手势结束和双击回到 1× 时都会走同一个 wy_clamp()：倍数贴近 1 就把 tx / ty 直接设成 0，并给 0.25s 过渡让它滑回中间。放大状态下则把位移夹在 (倍数-1) × 图片显示宽度 / 2 之内，所以永远拖不出边界。
Q4旋转屏幕为什么状态不丢？
倍数和位移都存在 JS 变量里，不是写在 DOM 上靠 CSS 维持。转屏只触发 resize， 代码重算边界、把位移重新夹紧一次，倍数保持不变。如果靠"每次重新初始化"就会归 1×， 那才是丢状态。
