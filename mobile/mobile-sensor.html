02

为什么必须做降级

FALLBACK

传感器是"有就有、没有就没有"的能力：台式机没有加速度计，部分安卓浏览器不发 devicemotion， iOS 还要用户点一下才给权限。只要代码写死成"等事件、等不到就什么也不做"，用户看到的就是一个永远停在 "摇一摇"三个字的页面——看起来像坏了，实际是没数据。

所以本页有三层：能摇就摇（正常路径）、等 1.5 秒没数据就明说"不支持"（状态反馈）、 再给一个"点我抽一次"（功能兜底）。抽到的菜和摇出来的完全一样，验收和演示都不受影响。

属性含不含重力静止时的值适合做什么
accelerationIncludingGravity 含 9.8 的重力 约 9.8（平放） 摇一摇：静止基线稳定，阈值好定
acceleration 已剔除重力 约 0 计步、纯运动强度分析；部分设备直接给 null 
// 合成加速度：三个轴平方和开根号
var wy_a = wy_e.accelerationIncludingGravity;
var wy_mag = Math.hypot(wy_a.x || 0, wy_a.y || 0, wy_a.z || 0);

// 阈值 + 冷却，两个都不能少
if (wy_mag > 18 && wy_now - wy_lastShake > 1500) {
    wy_lastShake = wy_now;
    wy_draw();
}

静止 9.8，摇一下 20～40 THRESHOLD

手机平放时合成加速度就是重力 9.8，所以阈值不能设成 5——那会一路触发。一次正常摇晃的峰值大约 20～40， 取 18 既能区分"拿起来"和"摇"，又不会摇断手才触发。1.5 秒冷却是为了"一次摇动只算一次"： 摇动过程中事件以每秒几十次的频率进来，没有冷却就会连抽七八道菜。

04

答辩准备

Q & A
Q1acceleration 和 accelerationIncludingGravity 有什么区别？
前者已经减掉了重力，静止时三个轴都接近 0，读数只反映"额外运动"；后者把重力也算进去， 静止时合成值约 9.8。摇一摇用后者：静止基线稳定在 9.8，阈值 18 就很好理解—— 相当于"在重力之外又叠加了 8 以上的加速度"。而且部分设备的 acceleration 直接返回 null， 用含重力的那个更稳。
Q2为什么阈值 18、冷却 1.5 秒？
静止 9.8，走路约 12～15，正常摇动峰值 20～40。取 18 能把"走路 / 拿起手机"和"摇"分开。 摇动期间事件每秒几十次，一次摇动会连续越过阈值，1.5 秒冷却保证一次摇动只抽一次菜， 同时人也不会觉得"要等很久才能再摇"。
Q3iOS 上为什么要按钮申请权限？
iOS 13 起，运动与方向传感器必须在用户手势里调用 DeviceMotionEvent.requestPermission()， 页面加载时自动调用会被拒绝。所以先显示一个"允许访问运动传感器"的按钮，用户点了才申请， granted 之后才开始监听，denied 就退回降级按钮。
Q4没有传感器时你的代码怎么走？
挂上监听后启动 1.5 秒计时，如果这段时间一条数据都没收到（或 accelerationIncludingGravity 是 null）， 就把状态标成"不支持"，显示提示条，并把"点我抽一次"作为主操作。计时器在收到第一条数据时清掉， 所以真机上不会误报。
